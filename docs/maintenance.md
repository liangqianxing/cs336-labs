# 维护说明

## 记录方式

学习目录与发布仓库分开：在原课程目录继续学习，在这里同步已经完成的代码和保留的官方测试。不要把整段聊天、个人文件路径、浏览器信息或 API 配置提交到公开仓库。

当前官方基础提交固定为 `a158843b20107949f1a8d7df1b05cd33b9166712`。`docs/snapshot.json` 保存每个同步文件的 SHA-256、文件大小、同步日期和源 Git 提交，不保存源路径。源 Git 提交不包含尚未提交的学习实现，因此应同时使用逐文件校验值识别实际快照。本轮更新只改变 `cs336_basics/attention.py` 与 `tests/adapters.py` 的代码校验值，新增不含 RoPE 的多头自注意力。更新官方版本时，应人工核对上游变更及许可证，再修改同步脚本中的来源记录。

## 每次更新

1. 在学习目录完成自己的实现，确认需要公开的内容。
2. 先使用 `--dry-run` 审阅白名单文件，随后运行同步。同步前会把所有文件读入内存并检查，拒绝符号链接、超过 8 MiB 的单文件和常见凭据特征。工具不会递归复制任意新文件，也不会操作源目录的 Git、删除源文件或自动提交。
3. 运行 `bash scripts/check_completed.sh`，根据实际结果更新 `docs/progress.md`。已完成新组件后，审阅并同时扩展脚本中的文件白名单、测试清单和文档状态。
4. 检查 `git diff --stat`、`git diff --check`、`git diff`，确认没有凭据或无关个人信息，再自行提交并推送。

凭据扫描是一层辅助检查，不能替代人工审阅。对于官方二进制 fixture 和作业 PDF，同步工具还要求它们与固定官方基础提交的内容相同；学习代码按原样复制，不自动修复、格式化或补齐 TODO。

## 测试范围

CI 只执行 `scripts/check_completed.sh` 中显式列出的 9 个测试，对应 8 组已实现组件。本轮增加 `test_multihead_self_attention`，验证没有 RoPE 的因果多头自注意力；RoPE 与含 RoPE 的多头自注意力用例继续排除。保留的其余官方测试用于未来学习，不能把当前 CI 通过理解为 Assignment 1 整体完成。增加范围时应更新同一份清单，避免本地与 CI 的验证目标不一致。
